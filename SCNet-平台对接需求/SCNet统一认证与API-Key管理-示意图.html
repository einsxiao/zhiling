2需求一 · 模式 A：OAuth 2.0 授权码 + PKCE（推荐）

标准授权码流程。用户密码仅提交到 SCNet；第三方通过回调获得授权码，再换取 token 与账户信息。桌面端可用回环地址接收回调。

sequenceDiagram
    autonumber
    participant C as 第三方应用
    participant B as 浏览器
    participant S as SCNet认证授权服务

    C->>C: 生成 state(防CSRF) + PKCE(code_verifier/code_challenge)
    C->>B: 打开认证页 authorize?client_id&redirect_uri&scope&state&code_challenge
    B->>S: GET /oauth/authorize
    alt 用户未登录
        S-->>B: 登录页(密码仅提交至SCNet)
        B->>S: 提交账号密码
    end
    S-->>B: 授权确认页(应用信息+权限清单)
    alt 用户同意
        B->>S: 确认授权
        S-->>B: 302 redirect_uri?code=xxx&state=xxx
        B->>C: 回调携带授权码 code
        C->>S: POST /oauth/token(code+code_verifier)
        S-->>C: access_token + refresh_token + userinfo
    else 用户拒绝
        S-->>B: 302 redirect_uri?error=access_denied&state=xxx
        B->>C: 回调携带拒绝错误
    end

3需求一 · 模式 B：授权请求 ID + 轮询（桌面端友好，知令同款）

桌面端不便接收浏览器回调时采用。第三方生成高熵 request_id，用户授权后轮询状态接口领取凭证。该机制即知令桌面端现有登录方式的通用化版本。

sequenceDiagram
    autonumber
    participant C as 第三方应用(桌面端)
    participant B as 浏览器
    participant S as SCNet认证授权服务

    C->>C: 生成随机 request_id(≥32位)
    C->>B: 打开 device?client_id&request_id&scope
    B->>S: GET /oauth/device
    alt 用户未登录
        S-->>B: 登录页
        B->>S: 提交账号密码
    end
    S-->>B: 授权确认页
    B->>S: 用户点击「同意授权」
    S->>S: 生成 token 并绑定 request_id
(5分钟拉取窗口)
    loop 轮询(间隔2~3s)
        C->>S: POST /oauth/device/status(request_id)
        S-->>C: pending(未授权)
    end
    C->>S: POST /oauth/device/status(request_id)
    S-->>C: authorized + access_token + refresh_token + userinfo
轮询状态机：pending（未确认）→ authorized（首次成功拉取，下发凭证）→ active（后续查询）｜denied（用户拒绝）｜expired（5 分钟超时或已撤销）。安全：HTTPS + 按 IP+request_id 滑动窗口限流 + 每用户活跃会话数上限。

4两个需求联动：授权后无感跑通大模型（端到端时序）

授权成功 → 查询已有 Key → 无 Key 则创建（返回完整 Key 一次）/ 有 Key 则读取明文 → 以 Key 调用推理端点。全程用户无手动操作。

sequenceDiagram
    autonumber
    participant U as 用户
    participant C as 第三方应用(知令)
    participant S as SCNet

    C->>S: 发起授权请求(scope 含 user:info + llm:apikey)
    S->>U: 展示登录页(未登录) / 授权确认页(已登录)
    U->>S: 输入账号密码(仅提交到SCNet)
    U->>S: 点击「同意授权」
    S->>C: 返回 access_token + 用户信息
    C->>S: 查询该用户已有的 API Key(读取接口)
    alt 无可用 Key
        C->>S: 创建 API Key(创建接口，返回完整Key)
    else 已有 Key
        C->>S: 读取 Key 明文(读取接口)
    end
    C->>S: 以 API Key 调用大模型推理端点
    S-->>C: 模型响应(流式/非流式)
    C-->>U: 第三方应用内直接使用大模型能力
