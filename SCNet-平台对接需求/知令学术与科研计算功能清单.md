## 1. 概述

**知令（ZHILING）** 是一款桌面端 AI 全流程工作平台，专为科研人员与工程师打造，将 **AI 智能体、代码与文档编辑、计算任务管理、远程集群对接** 无缝融为一体——用户可以用自然语言驱动 AI，完成从文献阅读、论文撰写、代码开发到作业提交的全链路工作（[README.md](../README.md)）。

本文按「学术研究」与「科研计算」两大场景，系统盘点知令当前**专为学术与科研计算用户开发的功能，以及对通用能力面向科研场景所做的强化**，作为 SCNet 对接评估与《知令对接超算互联网体验改善方案》中四大体验主题（大模型使用、任务管理、超算使用、专业学术体验）的**能力侧事实依据**。

**要点**：知令在「专业学术体验」与「任务管理 / 超算使用」方向并非从零开始——学术检索、科研模式、文献处理、计算任务管理、远程集群对接等核心能力均已上线运行，对接工作是在既有能力之上的**衔接与贯通**，而非新建。

## 3. 学术研究场景的专门功能

### 3.1 学术文献检索（<mark>学术搜索</mark>）

知令内置<mark>**学术搜索工具 `scholar_search`**</mark>，供智能体在对话中直接检索学术文献（[functions_scholar.jsx](D:/work/zhiling/front_ui/src/components/Agent/agentFunctions/functions_scholar.jsx)、`zhilingsite/agent/scholar_search_api.py`）：

- **多搜索引擎** ✅：支持 `auto`（自动选择）、`exa`（通用学术检索，推荐）、`parallel`（并行多源）、`native`（模型原生搜索）四种引擎；
- **多级检索深度** ✅：`quick`（快速）、`standard`（标准，默认）、`deep`（深度，更慢但更全面）三档模式；
- **学术域名白名单过滤** ✅：默认仅限学术域名内检索，内置 25 个权威学术域集合，包括 arxiv.org、pubmed.ncbi.nlm.nih.gov、nature.com、science.org、sciencedirect.com、ieeexplore.ieee.org、acm.org、springer.com、mdpi.com、frontiersin.org、plos.org、cell.com、pnas.org、aclanthology.org、openreview.net、biorxiv.org、medrxiv.org、researchgate.net 等；
- **结构化结果 + AI 综合摘要** ✅：返回编号文献条目（标题 / URL / 摘要），并附模型生成的综合摘要，直接注入对话上下文；
- **反幻觉设计** ✅：结果链接仅采纳学术域名（含子域名），对缺失结构化标注的回答文本再做 Markdown 链接兜底解析与过滤，幻觉链接被剔除（对应服务端测试 `zhilingsite/agent/test_scholar_search_api.py`）；
- **计费透明** ✅：学术搜索为站点计费功能，按次扣费并展示费用明细，采用 fail-closed 门禁（仅剩日赠送额度时不放行、零扣费请求被拒绝）；
- **全模式可用** ✅：所有智能体工作模式下均可按需加载调用。


### 3.2 科研工作模式（Research Mode）

知令为科研场景设计了**专用智能体工作模式「科研（Research）」**，系统提示词内置严谨的科研工作规范（[research.md](D:/work/zhiling/front_ui/src/assets/agent_modes/research.md)）：

- **严谨可核对** ✅：要求以「可靠的外部信息源（项目文件或网络搜索）」支撑论述，先澄清问题与假设再展开分析；
- **区分事实、推断与猜想** ✅：明确要求说明局限与不确定处，不把推测写成结论；
- **多角度审视** ✅：从不同模型、对立假设、边界条件审视同一问题，避免单一叙事，并给出可进一步验证的方向；
- **证据标注规范** ✅：重要观点尽量寻找可印证依据（文献要点、数据、实验设定、代码与日志），以 `[文件参考信息](/path/to/file)`、`[网络参考信息](https://source.content.page)` 形式标注，禁止凭空虚构引用；
- **学术化写作** ✅：使用专业术语与学术写作方式，支持 LaTeX 公式的规范化、论文化表述；
- **成果落地** ✅：工作成果优先持久化为 Markdown / HTML 文件。

围绕科研模式的**配套强化**：

- **科研模式 PDF 质量约束** ✅：科研模式下处理 PDF 时，系统强制智能体优先读取 `.md-cache/` 下与源文件同名的高质量 Markdown（`*.pdf.high.md`），避免误用标准质量或历史缓存版本（[AgentPromptFactory.jsx](D:/work/zhiling/front_ui/src/components/Agent/AgentPromptFactory.jsx)）；
- **计划文件科研实施入口** ✅：`*.plan.md` 计划文件支持「科研模式实施」——由科研智能体深入分析调研、逐项推进计划（[PlanFileViewer.jsx](D:/work/zhiling/front_ui/src/components/RichFilesView/PlanFileViewer.jsx)）；
- **自定义模式继承科研工具集** ✅：用户自定义工作模式可选择继承科研模式的工具策略，科研专用工具对继承模式同样可用；
- **新建会话模式继承** ✅：当前标签为科研模式时，新建会话默认保持科研模式，便于连续调研。

### 3.3 文献阅读与学术写作

- **PDF 阅读与云端高质量转换** ✅：内嵌 PDF 阅读器；PDF 可一键转为高质量结构化 Markdown（MinerU 云端转换），产出标准版（`*.std.md`）与高质量版（`*.high.md`）双层缓存，供智能体与用户查阅分析（[intro.md](../intro.md)）；
- **DOCX 原生编辑** ✅：Word 文档查看与编辑，支持正文、表格、图片、批注等操作，AI 辅助润色与格式调整；
- **Markdown → DOCX 转换** ✅：文档工具支持 Markdown 转 Word，便于论文/报告按期刊模板交付；
- **LaTeX / 公式渲染** ✅：Markdown 完整支持 LaTeX 数学公式（KaTeX 渲染），行间公式、化学式（\ce）、物理单位（\pu）等学术排版语法均可渲染；
- **图表嵌入写作** ✅：Mermaid 流程图、D3 / ECharts 可视化可直接嵌入 Markdown 文档；
- **AI 论文助手** ✅：AI 可跨文件理解项目上下文，辅助润色 LaTeX / Word 文档、提取文献 PDF 关键信息、生成综述初稿（[README.md](../README.md)）；
- **审稿通知处理** ✅：邮箱集成支持 IMAP/SMTP 多账户，智能体可代收审稿通知、辅助回复与流转。

### 3.4 多视角研讨与深度研究

- **圆桌 / 超级圆桌** ✅：主持人模式组织 2–5 个不同模型并行讨论同一议题，多轮迭代收敛，产出共识报告——适用于学术问题多视角论证、方案评审、文献观点碰撞（[roundtable.md](D:/work/zhiling/front_ui/src/assets/agent_modes/roundtable.md)）；
- **子会话深度研究** ✅：可派发 research 模式子会话独立承担调研任务（`delegate_to_sub_session`），主会话汇总结果，适用于文献综述、方法调研等大任务拆分；
- **超级任务模式（super_task）** ✅：按阶段编排、调度子会话协作实施长链路研究计划；
- **计划模式（plan）** ✅：面向超长链路、多依赖研究任务的拆解、排序与追踪，把庞杂目标落成可执行路径。

### 3.5 科研配图（<mark>图片处理</mark>）与多媒体理解

- <mark>**文生图 + 图修改** ✅</mark>：按需选择图像模型（如 Gemini 系列）生成论文配图；支持参考图输入对已有图片进行修改编辑（图生图），按张透明计费；
- **3D 结构图** ✅：`show_3d_cube_file` 工具可直接读取 `.dat` 格式矩阵数据，绘制 3D 立方体表面图并在会话中展示——契合材料模拟、场分布等科研数据展示需求（[functions_plot.jsx](D:/work/zhiling/front_ui/src/components/Agent/agentFunctions/functions_plot.jsx)）；
- **绘图模式（plot）** ✅：以数据可视化、媒体与结构展示为重点的专用模式，解读本地媒体文件与结构数据；
- **多模态媒体理解** ✅：对话可直接发送图片、视频、音频附件；非视觉模型自动生成媒体内容描述（MiMo 描述 fallback），实现「看懂」图表的统一体验；
- **视频生成与本地处理** ✅：AI 视频生成（时长/分辨率/比例可选、首尾帧引导）；本地 ffmpeg 视频信息查询、抽帧、裁剪、转码、拼接——适合实验录像与演示素材处理；
- <mark>**SVG 转 PNG** ✅</mark>：矢量图转位图工具，便于论文投稿图片格式统一。

## 4. 科研计算场景的专门功能

### 4.1 <mark>计算任务管理</mark>（.task 体系）

知令提供**统一计算任务体系**，将集群作业与本地脚本纳入同一套工作流（[计算任务.md](D:/work/zhiling/back_frame/resources/skills/计算任务.md)）：

- **统一任务文件（.task）** ✅：一套语法描述计算作业，同时支持 **SLURM 集群调度**与本地 **Shell 直接执行**；脚本按扩展名（.sh / .py / .lua 等）解析执行；
- **资源配置面板** ✅：队列、节点数（nodes / ntasks_per_node / ppn）、CPU、GPU、国产 **DCU 设备**（dcus）、墙钟时间（walltime）、节点白名单/排除等参数可视化配置，语义对齐 SLURM sbatch；
- **批量参数扫描** ✅：batch 定义支持 `set` 集合与 `list` 等差序列的**笛卡尔积**参数扫描，每个参数组合生成独立子任务（独立运行与日志目录），脚本内可通过环境变量（`PARAM_A`）或 `${A}` 占位符使用参数；支持 `job_id` 单独提交 / 重跑指定子任务；
- **AI 自然语言驱动** ✅：智能体可通过 `submit_task` / `get_task_status` / `terminate_task` 工具完成「提交 → 查询 → 终止」全流程，用户一句话即可驱动作业提交；
- **实时状态跟踪** ✅：提交后自动轮询排队 → 运行 → 完成/失败状态，任务视图实时展示状态与输出；
- **日志与结果** ✅：日志文件路径与预览随状态返回，输出支持 Plotly 图表内嵌展示；
- **大规模任务通道** ✅：任务系统提交上限 512 个，超量场景引导使用 SLURM 批处理（sbatch）或 nohup 后台运行；
- **队列环境感知** ✅：系统自动注入远程 `sinfo` 探测得到的当前队列/分区/资源信息，智能体提交前据此选择队列与资源。

典型科研工作流：编辑 VASP / LAMMPS 输入文件 → AI 检查参数 → 一键提交到超算 → 实时查看结果（[README.md](../README.md)）。

### 4.2 远程集群对接

- **SSH 远程项目** ✅：远程服务器的文件树、编辑、搜索与本地操作体验一致，像操作本地文件一样操作远程集群目录（[intro.md](../intro.md)）；
- **多标签远程终端** ✅：内置 SSH 终端，多标签并行，支持密码与密钥认证；本地 PTY 终端同框架可用；
- **连接池管理** ✅：统一 SSH 连接池，健康检查、闲置驱逐、连接重建限流；连接不可达时**快速失败**（统一超时 30 秒、三层快速失败判定），不再长时间卡等（[ssh_connection_pool_base.js](D:/work/zhiling/back_frame/src/workers/ssh_connection_pool_base.js)）；
- **远程操作稳定性** ✅：搜索层并发受限（stat 批量 16 并发）、find 命令超时、SFTP failFast 透传，远程大目录操作稳定可控。

### 4.3 数据可视化

- **Plotly 图表族** ✅：任务日志与数据文件支持 2D / 3D / 立方体表面图（cube surface）等绘图变体，计算结果无需导出即可内嵌分析（[plot_file_2d.jsx](D:/work/zhiling/front_ui/src/components/TaskView/plots/plot_file_2d.jsx) 等）；
- **多引擎渲染** ✅：Markdown 内嵌 Mermaid 流程图、D3 / ECharts 可视化，KaTeX 公式渲染；
- **数据库直连** ✅：PostgreSQL / MongoDB 连接查询，AI 辅助编写 SQL，查询结果就地可视化；
- **Jupyter 子服务** ✅：Electron 主进程可管理 Jupyter、Xming 等子服务，衔接科研常用工具链。

### 4.4 脚本执行与自动化

- **多行脚本执行** ✅：`run_script` / `run_inline` / `run_script_file` 三类工具覆盖单行命令、多行脚本与脚本文件执行，**自动识别 shebang 解释器**，无需手动指定（[runScriptToolCore.js](D:/work/zhiling/front_ui/src/components/Agent/agentFunctions/systemTools/runScriptToolCore.js)）；
- **定时与事件触发** ✅：定时任务按计划自动执行 AI 工作流；邮件到达等事件自动触发处理；自动任务支持一次性 / 周期执行；
- **GUI 桌面自动化** ✅：智能体可自动控制 Windows 桌面程序（启动应用、点击按钮、键盘输入等），辅助操作科研软件的图形界面。

## 5. 面向学术科研用户的专项强化

### 5.1 检索与引用可靠性强化 ✅

- <mark>学术搜索</mark>默认 `academic_only`（仅限学术域名），域名白名单含子域名匹配；
- 上游结果解析与回答文本兜底解析**双重过滤**，幻觉链接被剔除（`zhilingsite/agent/scholar_search_api.py`）；
- 科研模式要求证据标注与信息源验证，明确「不凭空虚构引用」。

### 5.2 文献处理质量强化 ✅

- MinerU 云端高质量转换 + `.md-cache` 标准/高质量双层缓存，复杂版式 PDF 亦可结构化；
- 科研模式下 `read_file` 对 PDF 强制走高质量转换结果，杜绝以低质量文本做权威来源（[createReadFileTool.js](D:/work/zhiling/front_ui/src/components/Agent/agentFunctions/systemTools/createReadFileTool.js)）；
- PDF 批量转换支持「跳过 / 覆盖」策略，适合文献批量入库。

### 5.3 稳定性与可靠性强化 ✅

- **会话持久化 v2**：消息按轮次增量落盘、防抖合并、并发守卫、损坏检测修复，长会话数据不丢失；
- **文件变更快照与回滚**：智能体改动文件前自动快照，支持逐条接受/回滚（accept/reject）；
- **崩溃守护**：应用异常终止检测、致命异常现场快照、网络类错误静默抑制（[crash_guard.js](D:/work/zhiling/back_frame/src/base_utils/crash_guard.js)）；
- **长时运行稳定**：修复长时间使用内存膨胀与卡顿（渲染内存 1GB→5GB 后崩溃问题已修复）、远程连接异常快速反馈（[更新日志](https://zhiling.hcow.cc/doc/更新日志/)）。

### 5.4 多平台与国产化环境 ✅

- 桌面端覆盖 **Windows / macOS / 麒麟 V10 / V11**，移动端 Android（i18n 中英双语）；
- 麒麟环境完善：AppImage 图标、窗口圆角、桌面快捷方式自动创建；
- 计算任务配置原生支持**国产 DCU 设备**配额（dcus 字段）。

### 5.5 成本与资源可控 ✅

- **工具级计费透明**：学术搜索、文生图、PDF 云端解析等独立计费工具按次计费，费用明细随结果展示（[usageCostUtils.js](D:/work/zhiling/front_ui/src/components/AgentManager/usageCostUtils.js)）；
- **模型价格透明**：模型菜单直接显示输入/输出价格与峰谷时段定价，按价格排序方便对比；
- **BYOK 自带 API**：支持自定义 Base URL / Model Id / API Key 接入自有模型资源；
- **免费体验机制**：未登录用户可申请 4 次 × 7 天免费试用（[更新日志](https://zhiling.hcow.cc/doc/更新日志/)）。

### 5.6 交互与协作体验强化 ✅

- **语音输入**：高精度语音识别，口述即指令，适合实验现场与不便打字场景；
- **记忆系统**：会话级与项目级双层总结与记忆，沉淀结论与关键决策；
- **成长系统**：持续梳理项目重点、查漏补缺，随使用加深领域理解；
- **圆桌多模型研讨**：单一议题多视角论证，收敛为共识结论；
- **用户补充暂停轮次**：智能体执行长任务过程中可暂停并补充信息后继续，协作不中断。

## 6. 对 SCNet 对接的支撑意义

本清单与《[知令对接超算互联网体验改善方案](./知令对接超算互联网体验改善方案.md)》的关系：

1. **「专业学术体验」主题已有扎实底座** ✅：学术检索、科研模式、文献处理、学术写作、配图与研讨能力均已上线，SCNet 对接后接入的算力、应用商城与 AI 社区资源可直接嵌入这条「文献 → 输入文件 → 计算 → 论文」的既有工作流；
2. **「任务管理 / 超算使用」主题已有成熟作业体系** ✅：`.task` 统一任务体系、SLURM/Shell 双模式、批量参数扫描、远程集群对接与可视化均已实际运行于用户自管集群，与 SCNet 作业 API 的映射具备现成的体验层框架；
3. **对接工作聚焦「衔接」而非「新建」** ✅：知令侧能力差距主要为「SCNet 身份与凭证的无感接入」（BYOK 手动通道之外的一键授权），这正是需求文档《SCNet统一认证与API-Key管理需求文档》所定义的最小闭环；
4. **工程化能力支撑联合运营** ✅：计费透明、稳定性、多平台（含国产化）与安全实践，为联合品牌的用户体验基线提供保障。
