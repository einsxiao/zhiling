Executive Summary

01执行摘要

面向 SCNet 管理层的一页式概述：为什么做、做什么、分几步、要什么决策。

👥 双方是谁

知令 ZHILING：桌面端 AI 全流程工作平台，覆盖「AI 智能体对话、文档与代码编辑、计算任务管理、远程集群对接、数据分析与可视化」全链路 ✅ 已具备

国家超算互联网平台（SCNet）：汇聚全国超算资源，已对外提供计算服务开放 API、大模型推理服务（OpenAI/Anthropic 兼容端点）与 Token Plan / Coding Plan 套餐 ✅ 已具备

🔌 断点在哪

SCNet 的身份体系、API Key、大模型能力目前只能通过网页控制台人工衔接第三方工具：手动创建 Key → 复制 → 回填，无法在桌面工作流中「登录一次、直接可用」。

结构性缺口 = 第三方授权 + API Key 开放接口 ⚠️ 依赖SCNet确认

🎯 三大主张
① 打通身份与凭证（最小可行闭环）

SCNet 开放「第三方统一认证授权（OAuth 式）」与「大模型 API Key 管理接口」两项能力，知令作为首批第三方应用接入。密码全程不出 SCNet、Key 自动准备。

② 由点及面拉通四大主题

依次打通大模型使用、任务管理、超算使用、专业学术体验：「写输入文件 → AI 检查 → 提交 SCNet 算力 → 结果回传可视化」成为一条直线。

③ 联合品牌共同运营

以「知令 ZHILING × 超算互联网 SCNet」联合品牌对外发布，形成「国家级平台 × 桌面工作台」的体验标杆，并向更多第三方应用复制。

🗺 分阶段落地（建议排期）

P0 立项联调 → P1 身份互通与大模型无感接入（1–3 个月）→ P2 任务管理打通（3–6 个月）→ P3 超算使用与算力体验（6–9 个月）→ P4 专业学术体验与生态运营（9–12 个月）。各阶段均有明确退出标准与验收用例。 🧭 建议值

决策请求：请 SCNet 管理层确认本文第 12 章待确认事项中技术类事项（尤其是 OAuth 端点、API Key 明文读取策略、应用注册审核流程），授权研发团队立项排期，并指定双方接口人进入 P0 联调。
Value Proposition

02合作价值

从 SCNet、知令、用户、生态四个视角看收益。

🏛 对 SCNet：把平台能力延伸进用户工作台
  • 大模型 API 用量与留存提升：消除「控制台复制 Key」环节，促进 Token Plan / Coding Plan 套餐活跃使用
  • 算力与应用的桌面级入口：VASP、LAMMPS、GROMACS、AlphaFold3 等应用直达「写文件 → 提交 → 看结果」工作流
  • 降低第三方接入门槛：开放 OAuth 与 Key 接口后，任何工具均可按同样标准接入，知令成为第一个「样板间」 🧭
  • 数据与凭证安全合规：用户密码仅出现在 SCNet 官方页面，Key 生命周期由 SCNet 管控 ✅⚠️ 落地依赖SCNet确认
  • 国家级平台的体验标杆：联合品牌作为生态合作示范案例对外宣传 🧭
💻 对知令：补齐国家级平台的用户体系与模型服务
  • 用户体系升级：新增「SCNet 账号登录」入口，覆盖高校、科研院所与工程机构的 SCNet 存量用户 🧭
  • 模型服务扩充：知令现有多模型与 BYOK 自带 API ✅；接入后用户订阅的 SCNet 套餐模型一键出现在模型列表 🧭
  • 借力平台公信力：官方合作增强知令在科研与工程用户群体中的信任度
👤 对用户：一次授权、无感可用、全流程统一
  • 省去手动步骤：不再「创建 Key → 复制 → 回填」；授权一次，Key 自动创建/读取、自动配置 🧭
  • 安全放心：密码只在 SCNet 官方页面出现；授权随时可在 SCNet 侧撤销 🧭
  • 体验统一：对话、任务提交、结果查看、文献阅读在同一工作台完成，减少 3~5 个工具切换 ✅ 已具备
🌐 对生态：可复制的第三方接入范式

沉淀「应用注册 → OAuth 授权 → Key 管理 → 推理调用」标准链路，形成 SCNet 开放平台的通用接入指南与 SDK，供后续第三方应用低成本复用。 🧭 规划建议

是否公开推广由 SCNet 决定 ⚠️

🔐 凭证与数据流
① 身份凭证

access_token（建议 2h）/ refresh_token（滚动续期）由 SCNet 签发，知令本地加密存储（与知令现有登录凭证同级安全要求 ✅ 的实践基础，落地方案待确认 ⚠️）

② API Key

仅在「创建响应一次」或「读取接口」两个受控出口出现；知令收到后本地加密保存，仅用于向 SCNet 推理端点发起调用，不对外发送（K1 约束）

③ 用户数据边界

密码永不进入知令；userinfo 字段范围（邮箱是否明文、是否含机构）由 SCNet 决定 ⚠️

④ 作业数据

任务元数据与日志经 SCNet 作业 API 回传知令展示；大文件结果沿用用户自管存储或 SCNet 用户存储 API ✅（配置方式待确认 ⚠️）

安全设计要点（沿用需求文档安全要求，落地依赖 SCNet 确认 ⚠️）：全程 HTTPS；授权码单次有效、state 强制校验；PKCE S256；轮询模式按 IP+request_id 滑动窗口限流；每用户活跃授权会话数设上限（S1–S3）；Key 明文与 token 不出现在任何日志；响应头 no-store（S8）；用户可在 SCNet 个人中心随时撤销授权，撤销后凭证立即失效（S7）。
Key Flows

07关键流程设计

四个核心流程，对应 P1–P4 各阶段的核心闭环。

🔑 流程一 · 一次授权、无感跑通大模型（P1 核心流程）
步角色动作
1用户点击「SCNet 账号登录」
2知令发起授权（scope: user:info + llm:apikey）
3SCNet登录页（未登录）/ 授权确认页（已登录）
4用户账号密码（仅提交至 SCNet）；同意授权
5SCNet签发 access_token + refresh_token + userinfo
6知令查询已有 API Key（读取接口）
7a知令无可用 Key → 创建 API Key（返回完整明文，仅此一次）
7b知令已有 Key → 读取 Key 明文（需 scope 授权）
8知令Key 本地加密存储，配置到推理客户端
9知令以 API Key 调用 https://api.scnet.cn/api/llm/v1
10SCNet模型响应（流式/非流式）
11用户工作台内直接使用大模型能力
对应需求文档 4.3 节「无感跑通大模型」闭环与端到端验收场景 U1–U8。⚠️ 全部接口依赖 SCNet 开发确认
📋 流程二 · 任务提交与状态追踪（P2）
  1. 用户在知令任务视图创建 .task ✅，目标选「SCNet」；
  2. 知令将 .task 参数映射为 SCNet 作业 API 提交请求（API ✅，映射 🧭）；
  3. 提交后知令轮询作业状态（排队 → 运行 → 结束），失败时结合错误码给出可读指引 🧭；
  4. 日志与结果文件回传知令任务视图，支持 Plotly 可视化 ✅；
  5. AI 智能体可用自然语言发起/查询/终止任务（知令工具链 ✅，SCNet 目标接入 🧭）。
⚙️ 流程三 · 算力与应用的衔接（P3）
  1. 用户在知令「SCNet 资源」入口查看算力与应用信息（跳转官方页面，展示形式待确认 ⚠️）；
  2. 高频应用（VASP/LAMMPS/GROMACS 等）提供知令模板：输入文件骨架 + AI 参数检查清单 + 对应 .task 🧭；
  3. 任务产出（结构/能量/轨迹）用知令可视化与 AI 解读（✅＋🧭）；
  4. 算力购买、套餐订阅等交易环节始终在 SCNet 官方页面完成，知令不代收代付（边界见第 11 章）。
📚 流程四 · 文献到计算的学术闭环（P4）
  1. 用户在知令打开文献 PDF → 高质量转 Markdown ✅（MinerU）；
  2. AI 提取方法、参数与软件版本 → 生成输入文件草稿 🧭；
  3. 用户确认后经流程二提交 SCNet 算力 🧭；
  4. 结果对照文献数据，AI 辅助分析差异 → 写入论文/报告（文档能力 ✅）。

Risk & Boundaries

11风险与边界

八项风险与缓解措施，以及双方边界约定。

⚠️ 风险清单（R1–R8）
R1 · 安全与凭证风险 高

API Key 明文经由第三方存储，存在泄露面。

缓解：本地加密存储、最小权限 scope、撤销即时生效、审计日志（需求文档 6.4/S 系列）；Key 明文策略以 SCNet 确认为准 ⚠️
R2 · 隐私合规风险 中

userinfo 字段（邮箱/手机号/机构）返回范围不明确。

缓解：按 SCNet 隐私政策分级返回/掩码，字段清单待确认 ⚠️
R3 · 排期与依赖风险 高

OAuth 与 Key 接口是 P1 硬依赖，若 SCNet 排期推迟则整体顺延。

缓解：需求文档已给出完整接口建议；P0 尽早锁定排期与接口人。
R4 · 体验一致性风险 中

SCNet 认证页面与知令 UI 体验割裂、授权文案不一致。

缓解：授权页需求已在需求文档 5.4/5.5 定义；双方 UI 评审。
R5 · 接口变更风险 中

SCNet 接口路径/参数后续调整，知令适配层需跟随。

缓解：版本化接口约定、变更通知机制（待确认 ⚠️）。
R6 · 商务政策风险 中

计费政策、商城入驻政策、分成模式未定。

缓解：商务条款单独谈判，技术联调与商务谈判并行。
R7 · 用户预期风险 中

用户把「无感接入」误解为「算力免费/不限量」。

缓解：授权页与知令界面明确套餐范围；不做未核实的价格承诺。
R8 · 平台政策变化 低

SCNet 开放策略调整（如第三方接入范围收窄）。

缓解：以正式协议固化接入承诺与过渡期。
🚧 知令的边界（本方案明确不做）
  1. 不接触、不存储用户 SCNet 密码；不要求用户在任何知令界面输入 SCNet 密码；
  2. 不代收代付、不代理销售 SCNet 算力与套餐，交易环节全部在 SCNet 官方页面完成；
  3. 不将 SCNet 用户数据、Key、用量数据用于合作范围之外的商业用途；
  4. 不在未经 SCNet 确认的情况下，声称获得 SCNet 任何排他性授权或代表 SCNet 官方承诺（价格、SLA、扩容等）。
🏛 SCNet 的边界（建议双方共识 🧭）
  1. Key 生命周期、套餐权益、用量规则的解释权与最终控制权在 SCNet；
  2. 知令侧适配层对 SCNet 接口的调用须遵守 SCNet 限流与使用条款；
  3. 联合品牌物料需双方互审后发布。

Conclusion

14结论

  1. 体验断点是真实且可消除的：SCNet 拥有完备的计算与模型开放能力 ✅，知令拥有成熟的工作台产品 ✅，当前唯一的结构性缺口是「第三方授权 + API Key 开放接口」⚠️ 依赖SCNet确认，技术方案已在需求文档中完整给出，含接口规格、安全要求与 11 项端到端验收场景。
  2. 最小闭环价值集中：P1（身份互通与大模型无感接入）即可兑现「一次授权、直接可用」的核心体验改善，投入可控、见效最快，是双方合作的第一个确定性收益点。
  3. 蓝图清晰、可逐步兑现：四大主题（大模型使用、任务管理、超算使用、专业学术体验）与 P0–P4 路线图把「体验改善」拆解为可验收的里程碑，每一阶段都有明确的退出标准与量化指标。
  4. 合作模式成熟可复制：以「知令 ZHILING × 超算互联网 SCNet」联合品牌起步，沉淀的接入范式可复制给更多第三方应用，放大 SCNet 生态效应。
  5. 下一步行动：请 SCNet 侧确认第 12 章待确认事项并指定接口人，双方即进入 P0 立项联调，按第 13 章验收标准推进。
